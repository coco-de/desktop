이슈 #9 · chore/9-dia-remote-debugging → main

무엇을 바꿨나

macOS의 OpenCode·Claude Code 기본 chrome-devtools MCP를 실행 중인 Dia에 연결하도록 바꿨습니다. 설치 시 현재 사용자의 Dia 프로필 경로를 공백까지 포함한 하나의 실행 인자로 저장합니다.

구현 커밋 cebe95f · 구현·문서·검사 7개 파일: 111줄 추가, 9줄 삭제. 작업내역 HTML은 별도 문서 커밋으로 남깁니다.

  • macos/mac-setup.sh: --autoConnect와 Dia --user-data-dir 등록, 설정 확인 출력, 사용자 활성화·재연결 안내.
  • macos/README.md: Dia에서 디버깅을 켜는 순서, 연결 허용 창, 등록과 실제 연결의 구분.
  • windows/README.md·linux/README.md: Dia 미지원과 Chrome 대응 설명.
  • README.md: 브라우저 디버깅의 플랫폼별 대상과 PR 검사 안내.
  • tests/test_default_mcp.py: 두 클라이언트의 Dia 인자·기존 등록 갱신·경로 보존 검증. 세 플랫폼 비교에서 macOS 연결 인자만 좁게 정규화.
  • .github/workflows/default-mcp.yml: 기존 회귀 검사·Bash 문법·PowerShell 검사의 최소 PR/푸시 실행 배선.

왜 이 연결 방식인가

스크린샷의 Dia는 127.0.0.1:9222에서 서버를 실행합니다. 실제 리스너가 Dia임을 확인했지만 /json/version과 /json/list는 HTTP 404를 반환했습니다. 따라서 HTTP 주소로 조회하는 --browser-url만으로는 이 환경에 연결할 수 없습니다.

Dia는 ~/Library/Application Support/Dia/User Data/DevToolsActivePort에 포트와 WebSocket 경로를 기록합니다. Chrome DevTools MCP의 자동 연결 구현은 사용자 데이터 경로를 지정하면 이 파일을 읽어 실행 중인 브라우저에 연결합니다. 포트·재시작마다 바뀌는 WebSocket 식별자를 고정하지 않는 방식입니다.

근거: Chrome DevTools MCP BrowserManager, 공식 연결 옵션, 로컬 Dia 서버·프로필 파일 확인.

여기부터 리뷰하세요

  1. 설치 스크립트 6.6단계: 공통 정의에 Dia 연결 옵션만 추가하고 기존 백업·병합 경로를 재사용하는지 확인합니다.
  2. Python 회귀 검사: 실제 설치 블록을 임시 홈에서 실행하며 신규 설치·기존 등록 갱신·멱등성·다른 설정 보존을 확인합니다.
  3. 세 플랫폼 README: macOS의 수동 활성화와 Windows·Linux 대응이 설정과 맞는지 확인합니다.
  4. 최소 CI: 설치 스크립트 전체나 실제 토큰·개인 브라우저를 사용하지 않고 기존 검사를 실행합니다.

로컬 검증

  • Python 회귀 검사 7개 통과. OpenCode CLI가 실제 생성된 설정과 Dia 실행 인자를 수용함을 확인했습니다.
  • Docker PowerShell에서 Windows 파서·MCP 병합·인코딩·멱등성·오류 격리 검사 통과.
  • macOS·Linux Bash 문법 검사, actionlint, diff 공백 검사 통과.
  • ShellCheck의 경고 3건은 기본 브랜치에도 같은 코드에 존재하며, 변경 부분의 신규 경고는 없습니다.
  • 읽기 전용 코드 리뷰: 차단할 발견사항 없음.
  • 실제 MCP 서버 초기화 성공. Dia 탭 조회는 연결 허용을 기다리다가 60초에 종료됐습니다. Dia에 접근 가능한 창이 없어 허용 창을 확인할 수 없었으므로 실제 탭 조회 성공은 미검증입니다.

실행 기록

계획 승인 후 구현부터 머지까지 진행하는 정책입니다. ZenHub 워크스페이스 조회 실패로 작업 기록은 GitHub 이슈·PR에 남깁니다. 규모 보조 판정은 scale=deliberate였으며, 실제 변경 범위와 PM 정제로 단독 Task·3 SP를 확정했습니다. 제품 화면 개발이 없어 디자인 결정 기록은 없습니다.

기존 다른 MCP·Playwright의 Chrome 자동화는 그대로 사용합니다. Dia 허용 체크박스와 브라우저 설정 파일을 자동 조작하지 않습니다.
