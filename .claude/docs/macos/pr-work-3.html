macOS 서명 키체인 로그인 자동 해제

이슈 #3 · feature/3-macos-signing-keychains → main

파일 키체인의 자동 잠금 설정과 서명 키 접근 권한을 확인하고, 사용자 로그인 뒤 키체인을 자동으로 여는 선택형 macOS 설정을 추가했습니다. 최초 등록은 1Password 원본을 사용하고, 로그인 실행은 login 키체인의 암호화 사본을 사용합니다.

여기부터 보세요

  1. macos/signing-keychains/helper.m: 암호의 메모리 처리, 제한된 캐시 ACL, UI 없는 잠금 해제, 기존 partition 보존을 확인합니다.
  2. macos/signing-keychains/setup.py: 대상 경로 탐색, helper 서명·설치, LaunchAgent 등록, 실제 반복 서명 검증을 확인합니다.
  3. macos/signing-keychains/test-helper.m 및 tests.py: 다른 프로세스의 캐시 읽기 거부, 실제 잠금 주입, 빈 암호, ACL 멱등성, Installer 정책 분리를 검증합니다.
  4. macos/mac-setup.sh: --keychains-only가 전체 설치와 분리되어 실행되는지 확인합니다.
  5. macOS 안내와 Windows·Linux 차이 표: 실행 방법과 macOS 전용 근거를 함께 기록했습니다.

설계 판단

로그인마다 1Password CLI로 암호를 조회하면 1Password 잠금 해제나 접근 승인이 다시 필요할 수 있습니다. 원본은 1Password로 관리하되, 로그인 키체인의 암호화 사본을 전용 helper 하나만 읽도록 제한했습니다. LaunchAgent에는 실행 경로와 설정 파일 경로만 넣습니다.

암호를 명령행 -p·-k로 넘기거나 평문 파일에 쓰는 방식은 사용하지 않습니다. 파일 키체인의 ACL을 다루는 공개 Security.framework API가 필요하므로 Objective-C helper를 사용합니다. 정상 ACL은 유지하고 누락 도구·partition만 보완합니다.

Installer 인증서만 있는 장비에서는 로컬 ad-hoc helper 서명을 지원합니다. 앱 접근은 해당 helper의 코드 식별자로 제한됩니다. helper를 갱신할 때는 기존 대상 모두의 원본을 다시 지정해 캐시 접근 권한을 연결합니다.

공유 항목에서 최초 이전할 때는 보호된 표준입력 파이프를 지원합니다. 해당 경로에는 공유 URL이 저장되지 않습니다. 원본 자동 갱신을 사용하려면 실제 op:// 참조를 연결해야 합니다.

상태 점검은 조회 명령의 성공만 확인하지 않고 자동 잠금·신뢰 앱·partition 누락도 실패로 판정합니다. 로컬 파일 모드는 전용 디렉터리·helper 0700, 설정·로그·LaunchAgent 0600으로 확인했습니다.

운영 조건과 검증 범위

  • 사용자 로그인 시 login 키체인이 정상적으로 열려야 합니다. 로그인 전에 실행되는 시스템 데몬용 설정은 아닙니다.
  • 실제 재부팅은 수행하지 않았습니다. 로그인 작업 재실행과 실제 잠금→해제로 검증했습니다.
  • Fastlane이 임시 키체인을 재생성해 암호를 변경하면 원본과 로컬 암호화 사본도 갱신해야 합니다.
  • 검증 패키지는 설치하지 않습니다. 검증·전달용 임시 파일과 서버는 정리했습니다.
