OpenAI API 키(OPENAI_API_KEY) 1Password 자동 주입

이슈 #7 · feature/7-openai-api-key → main

팀이 쓰는 OpenAI API 키를 팀원이 손으로 복사·붙여넣지 않도록, 기존 팀 공용 토큰(ZenHub·Jira·Slang GPT·DCM·Slack·TypeSafe)과 같은 방식으로 1Password 팀 금고에서 읽어 환경변수 OPENAI_API_KEY로 자동 주입합니다. 세 OS(macOS·Linux·Windows) 스크립트와 README를 함께 바꿨고, 키 값은 이 저장소 어디에도 들어가지 않습니다. 저장소에는 op:// 참조 경로만 남습니다.

여기부터 보세요

  1. macos/mac-setup.sh — 가장 먼저 읽을 곳입니다. 참조 상수 OPENAI_TOKEN_OP_REF, 주입 헬퍼 3종(strip_·_is_empty·inject_), 새 8.11단계를 보세요. 모두 바로 위의 TypeSafe(8.10)와 같은 모양입니다. 이어서 --env-only 요약(마무리 단계는 8.12로 이동), 10단계 설치 검증, 마지막 안내 문구를 확인합니다.
  2. linux/linux-setup.sh — macOS와 같은 구조에 로그·경고는 Linux 규칙(warn·ok·info, 비밀값은 쓴 뒤 unset)을 따릅니다. 8단계가 ~/.zshrc를 팀 원본으로 덮어쓸 때 토큰 줄을 건져 두는 목록(PRESERVED_TOKENS)에 OPENAI_API_KEY가 추가된 것이 Linux 고유 변경입니다.
  3. windows/win-setup.ps1 — 새 8.5-g 단계는 기존 Set-CocodeTeamSecret 한 줄 호출입니다. -EnvOnly 요약·검증·사용법이 함께 바뀌었습니다. UTF-8 BOM과 CRLF는 그대로입니다.
  4. 세 README.md — 단계 번호(8.5~8.11), 토큰 목록, 검증 출력 예시, 문제 해결 표가 스크립트와 같은 내용을 가리키는지 봅니다. 특히 macOS README의 "OpenAI 키(OPENAI_API_KEY)는 무엇에 쓰나요" 단락이 이번에 새로 쓴 설명입니다.

설계 판단

결정근거와 대안신뢰도
1Password 참조는 op://API Token/OPENAI_API_KEY/credential 팀 'API Token' 금고에 같은 이름의 항목(API 자격 증명 유형)이 있고, 그 안에 값을 담는 credential 필드(비공개 유형)가 있는 것을 항목 구조만 조회해 확인했습니다(값은 읽지 않음). 최근 항목들이 환경변수 이름 그대로 이름 붙는 흐름이라 그 이름을 따랐습니다. 필드명은 TypeSafe·Slang GPT와 같은 credential입니다. 높음 (값 읽기는 아래 "검증 범위" 참고)
MCP 등록 없는 단일 값 패턴 OpenAI 공식 SDK(Python·JavaScript)가 환경변수를 직접 읽습니다. Slang GPT·TypeSafe와 같은 구조를 재사용해 새 헬퍼 설계를 만들지 않았습니다. 높음
macOS·Linux는 8.11단계 신설, --env-only 마무리는 8.12로. Windows는 8.5-g TypeSafe 추가(#2) 때 8.10을 만들고 마무리를 8.11로 민 방식 그대로입니다. 단계 번호가 나오는 모든 곳(주석·로그·검증·README 11곳 이상)을 같이 갱신했습니다. 높음
개인 키 처리는 기존 토큰과 같은 동작: 팀 키가 ~/.zshrc 맨 끝에 적혀 ~/.zshrc.local의 개인 키보다 우선하고, ~/.zshrc 안의 기존 export OPENAI_API_KEY= 줄은 교체됩니다. Windows는 같은 이름의 사용자 환경변수가 교체됩니다. 대안은 "이미 값이 있으면 건너뛰기"였지만, 그러면 이 변수만 다른 토큰과 동작이 갈라지고 키 교체(회전) 때 낡은 값이 남습니다. 대신 OpenAI 키는 개인용을 쓰는 사람이 많아 영향이 크므로 README에 우선순위, 교체 사실, 우회 방법(프로젝트 폴더의 direnv .envrc, Windows는 PowerShell 창 단위 설정)을 명시했습니다. 중간 — 팀 합의가 필요한 정책이라 재검토 대상
Linux PRESERVED_TOKENS에 추가 이 목록에 없으면 전체 재설치 중 ~/.zshrc를 덮어쓸 때 이미 주입된 줄이 사라지고, 1Password가 잠겨 있으면 다시 채워지지 않습니다. 높음

검증 범위 — 확인하지 못한 것

  • 실제 금고에서 키 값이 읽히는지는 이 환경에서 확인하지 못했습니다. 1Password 앱의 CLI 승인 창이 제때 승인되지 않아 op read가 authorization timeout으로 끝났습니다. 항목과 credential 필드의 존재, 그리고 위 가짜 op 시험으로 참조 경로·저장 로직은 확인됐지만 값이 비어 있지 않은지는 미확인입니다. 머지 후 ./macos/mac-setup.sh --env-only(Windows는 .\win-setup.ps1 -EnvOnly)의 요약에서 OPENAI_API_KEY: ✓ 주입됨이 나오는지 확인해 주세요.
  • Windows의 사용자 환경변수 쓰기(Set-UserEnv)와 실제 Windows·Ubuntu 데스크톱 전체 설치는 이 환경에서 실행하지 않았습니다. Windows는 주입 함수를 모킹 환경에서, Linux는 컨테이너에서 확인했습니다.
